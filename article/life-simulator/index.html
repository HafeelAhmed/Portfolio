Life Simulator

When I built Grid Evolution, I kept the simulation independent of the renderer so I could use it in Unreal one day. This project does that. The same creatures, brains and evolution run inside Unreal Engine 5.8, and the grid is replaced by smooth, continuous movement.

Why I made it

In Grid Evolution the simulation never touches the renderer, and raylib only draws it. I wanted to check that this held up with a different engine on top, so I moved the simulation core into Unreal and let Unreal handle the drawing, input, camera and UI.

I also wanted the creatures to move more naturally. On a grid they jump one cell at a time. Here they steer with a heading and speed, have inertia, push each other aside, and glide smoothly at any frame rate.

From a grid to continuous space

Most of the core carried over unchanged: the random number generator, the network and forward pass, evolution, the best-brain tracking, the energy economy, the fitness formula, episodes and the brain file format. What had to change was everything that assumed cells.

A 5×5 cell view means nothing without cells, so each creature now sees the world as 8 pie slices around its body. Each slice reports how close the nearest food, creature, Destroyer and wall are, and how much energy the nearest body has. This maps well to steering, since "food in my front-left slice" easily becomes "turn left a little". Because the network shape changed, the old grid brains can't be loaded, so I trained new ones.

Making movement cost energy

With the original energy numbers, continuous movement made life too easy. A creature gliding at full speed sweeps a lot of ground and eats on contact, so even random brains survived to the 5,000 tick cap on 4 of 5 seeds. In the grid version they died out after about 386 ticks. With no pressure to survive, evolution has nothing to select for.

To fix this, moving now costs 0.5 energy per metre. Random brains die out again, and trained ones keep going. Tested on 8 seeds the brain had never seen, with a 3,000 tick cap:

Trained creatures hunt the Destroyers

The fitness function pays a big bonus for killing a Destroyer, and in continuous space a group of creatures can surround one while it stands still to attack, and chip away at it from several sides. The trained population now goes after the Destroyers on purpose. In the run below, 8 of the 9 were gone within 400 ticks.

The Unreal side

The simulation core never includes an Unreal header. It's compiled into the game module, and the same source files also build a standalone trainer and test runner with CMake. One actor, ALifeSimManager, owns the simulation, and it is the only place where simulation types are converted to Unreal types.

01

Fixed timestep with interpolation

The simulation runs in whole ticks at a chosen speed (1 to 640 ticks per second, or max), with a 12 ms budget per frame so it can't stall the game. Each body's pose is interpolated between the last two ticks, so movement stays smooth at 60 fps even at 5 ticks per second.

02

Instanced rendering

Everything is drawn with Instanced Static Mesh components and one material that reads colour and glow from per-instance custom data. Instances are never removed, only hidden and reused, and each component gets one batched transform update per frame.

03

Input and HUD in code

All Enhanced Input actions and the mapping context are created in C++, so there are no input assets to maintain. The HUD shows world stats, a best-fitness-per-episode chart and an inspector for the selected creature, including its live brain output.

Problems along the way

The first problem was name clashes. Unreal has globals like GWarn and GEngine, so a file-local constant with a similar name became an ambiguous symbol. Several simulation files also use helpers with the same name in anonymous namespaces, which collide in Unreal's unity builds, so I turned unity builds off for this module.

The colours also looked washed out, because auto-exposure brightened the mostly dark arena, so I set a fixed manual exposure on the camera. The energy colour (blue when full, red when starving) looked pink in the middle, because blending in HSV passes through magenta, so I switched to a plain RGB blend.

Training

The headless trainer runs the exact same simulation code at about 11,500 ticks per second on one CPU core. The brain the game loads at startup took 400 episodes, about 70 seconds. Inside the game you can also turn the speed to max and watch evolution happen, at about 7,000 ticks per second with everything still being drawn.
